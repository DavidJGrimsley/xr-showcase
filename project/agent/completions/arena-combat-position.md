# Arena four-punch finisher and Position controls

October 10, 2026. Follow-up on `arena-multiplayer`, draft PR #5. This supersedes the fixed punch-hand sequence and Arena Height control in the earlier records. Historical Phase 2 and physical multiplayer acceptance remain incomplete.

Punch now uses four attacks per cycle. The authoritative controller randomly chooses left or right each time a punch actually starts; repeats are allowed. Buffering, retries and rejected inputs do not choose a hand or advance the count until the next attack starts. Each fighter has an independent cycle. Uppercut hands still alternate independently.

When the fourth punch connects without a knockout, it adds 0.75 seconds to the ordinary HitFront stun, for approximately 1.32 seconds total. The existing HitFront clip plays once and holds its final pose until recovery. The attacker's Uppercut button gets a large static glow and border in the active theme's secondary color, plus the label Uppercut!. The cue only appears when Uppercut is available and there is enough remaining stun for its manifest-defined hit event. Starting an uppercut, taking a hit, genuine interruption, expiration or a round reset clears the opportunity; portrait freezes it with the combat clock. Missed or interrupted finishers grant no opening. Damage and three-second uppercut cooldowns are unchanged. CPU and both humans use the same rule; simultaneous finishers cannot grant an ordering-dependent cue.

Arena Transform now replaces Height with Position. Position swaps the panel for X (left/right), Y (up/down), and Z (forward/back) native sliders with centimetre readouts. Done returns to Transform. X/Z use -5 to +5 feet and Y retains the surface-to-5-feet limit. The entire arena and both fighters move together in the fixed placement axes; changing yaw or scale leaves the selected position fixed, and camera viewing position never changes those axes or combat distances. The position panel and shared slider component are reusable. Other experiences retain their existing Height control by default.

Only solo or the multiplayer host can edit during the initial lobby. Scope guards, upload locking, first-countdown locking and Ready invalidation also apply to Position. Reposition and preview-to-hosted-frame conversion retain all offsets without restarting capture; existing-room Restart AR retains the adjusted pose. Protocol and invite version advance to 3 because authoritative transforms and fighter snapshots gained fields. Older peers and invitations are rejected clearly; reload both development clients from the current Metro server and create a fresh invite.

The development-only Test fighter clips control is now labeled Preview animations (dev), with an explanation that it plays a chosen fighter animation without combat. It remains useful for physical animation validation and is excluded from production builds.

All 120 Arena tests pass, including packaged hashes, embedded resources, all 23 clip names and GLB repairs. Existing AR/Qubit/Medical suites, lint/Prettier, TypeScript, Expo Doctor (21/21), iOS export and diff checks pass. Final MDS Doctor CI scores 99 with zero blocking errors; React Doctor has zero errors and 12 advisory warnings. Regressions cover random sampling at attack start, the four-punch reset, uppercut follow-through, missed finishers, cooldown suppression, simultaneous finishers, portrait holds, true interruptions, rematches, guest authority and cue synchronization, position limits and stale scopes, Ready invalidation, preview/shared placement retention and compatibility checks. The original assets and animation manifest are unchanged.

This is a JavaScript/UI change with no new native dependency; the previously delivered development client can run it from Metro. Physical iPhone checks remain pending: actual secondary-color glow over the camera view, simultaneous touches and readable cooldown feedback, the finisher's perceived timing, sliders in both landscape directions, and adjusted shared placement. The previously reported Viro relay failure remains unresolved, so simulated transport tests do not claim two-phone acceptance.
